# 掲示板の軽量化・切替基準

この文書は、非公開の開発版を「軽い・分かりやすい・一部が失敗しても使える」状態に保つための実装基準です。PvP本番のコード、データ、集計処理には接続しません。

## 画面を軽く保つ目標

- 初回の動画一覧では、`/api/media` を一度も呼ばない。カードは名前・再生導線・返信数だけを表示する。
- 動画を開いた詳細画面だけがプレイヤーを1つマウントする。`preload="metadata"` とHTTP Rangeで、再生位置の周辺だけを取得する。動画APIはRangeなし・open-endedを含む1レスポンスを4 MiB以下に制限し、200 MiB全体を返さない。
- コメントは1回20件、返信は押した時に最大20件。新着確認は可視タブの件数だけを45秒間隔で確認し、本文を勝手に差し込まない。
- 画像と外部サムネイルは遅延読込し、表示領域を先に確保する。動画の自動再生・一覧の先読みは行わない。
- Mutation後に全件再取得・全画面Loading・ページ再読み込みを行わない。対象投稿・投票欄・アップロード欄だけを更新する。

目安として、実機計測では初回LCP 2.5秒以下、CLS 0.1以下、主要操作のINP 200ms以下を確認します。数字を満たすために、測定なしの大規模な書き換えや依存ライブラリ追加はしません。

## 動画の保存と再生

アップロードは8 MiB単位の再開可能なMultipartでR2へ送り、掲示板DBにはメタデータだけを保存します。再生時は同じオブジェクトへRangeアクセスするため、アプリケーションサーバーが200 MiBを中継・保持しません。ブラウザのキャッシュは利用者単位の短い範囲に限定し、失敗時は動画部分だけを再試行します。

一覧で本物の先頭フレームを生成する処理は、動画処理Workerが用意できるまで追加しません。現在のカードは黒い空欄ではなく、ファイル名と「タップして再生」を表示します。Worker導入時も、静止画ポスターを通常の遅延画像として差し替えられる契約を維持します。

## エラーを広げないルール

- 0件（`success/empty`）とAPI障害（`error/stale`）を別表示にする。障害時に0件へ変換しない。
- Abort・request sequence・有限Retry・Timeoutを維持し、古いレスポンスを最新画面へ適用しない。
- 動画・翻訳・コメント・投票・統計の境界を分け、1機能の描画/APIエラーで他の領域を消さない。
- 書き込み障害ではRead-onlyへ縮退し、閲覧と前回正常値を残す。ログには操作名・時間・成功可否・エラー種別だけを記録し、本文や個人情報を保存しない。

## 新キャラの切替基準

月の変更だけでは掲示板を切り替えません。`lib/rules.ts` の台帳に、正確なキャラクターID・画像・JSTリリース月・`confirmed: true` がそろった項目だけを登録します。現在月の初回表示時に確認済み項目だけを一度だけSeedし、過去月のDB行はそのまま閲覧できます。未確認IDや画像だけが存在する場合は自動採用せず、空の月として明示します。

## 確認コマンド

変更後は次を実行し、既存PvP側を触っていないことを確認します。

```sh
npm run build
node --test tests/*.test.mjs
```

実機確認では、動画0件・動画50件・コメント500件・Slow 4G・動画再生中のコメント操作・通信切断後の再試行を確認します。測定結果や未修正事項はリリース前に記録します。
